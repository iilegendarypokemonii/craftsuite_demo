How it works

Every app works from typed commands.

Each Craft app has a command-line tool: a way to control the app with typed commands. A script can run these commands. An AI assistant can also write them for you. The result is normal files that you can open and change.

The request for this page, shortened

Request

Make a showcase page for all 12 Craft apps. Use 1 example: social media research on how AI language models developed in 2026. Make the media with the apps themselves. Run everything in the background.

  • Each app ran its own list of steps. It read the files of the step before, then saved normal files: Excel, Word, PowerPoint, PDF, PSD, MP4 and more.
  • 4 groups of 3 apps ran at the same time. Each group made its first files in about 15 minutes.
  • No app window opened. All work ran in the background while a person used the same PC.
  • The tools have limits. The notes at the end of the page list more than 40 workarounds.

The example project

Signal & Noise 2026

A small research team asks: how did social media talk about AI language models from January to September 2026? The team gives each post 1 of 10 themes. Then it measures each theme's share of the conversation.

AI that writes code became the biggest theme.

How the team measured

Share of the conversation is the number of posts about a theme, divided by all AI posts in that month.

The sample has 387 posts from 6 platforms. In this invented study, a person reads each post and gives it a theme and a tone. A real study takes a sample like this from a much larger stream of posts.

All data on this page is invented: the posts, the accounts and the research team. In the images, "hand-coded" means that a person of the invented team gave each post a theme. The 387 posts reuse 30 example texts. No quote comes from a real person.

GridCraftSpreadsheets · like Microsoft Excel

Turn raw posts into clear numbers.

GridCraft is a spreadsheet app, like Microsoft Excel. It opens and saves .xlsx files. It can also work from typed commands.

Get GridCraft, free

In this project

GridCraft calculated the numbers for Signal & Noise 2026. It imported 387 posts from a CSV file. Each post has 1 theme and 1 tone label: positive, neutral or negative. COUNTIFS formulas counted the posts for each month and theme. Other formulas calculated the share of the conversation and the % negative from these counts. GridCraft then drew 3 charts and printed the Summary sheet to PDF. WordCraft and PdfCraft used 2 of these charts.

Ideas for your own work

  • Make a formatted report with charts from a monthly CSV export.
  • Calculate shares and changes with COUNTIFS formulas. The results update when the data changes.
  • Print a summary sheet to PDF automatically every night.
  • Check 1 number fast. Get 1 answer from a saved workbook with 1 typed formula.

Notes for people who write their own commandsTechnical details for each command-line tool: what worked and what needed a workaround.

GridCraft. All work ran through gridcraft-cli with no window: run, convert, eval, info and cat. GridCraft has no command that saves a sheet as an image. GridCraft printed each sheet to PDF, and pdfcraft-cli render made the PNG. range.fill reads formulas relative to cell A1, so each formula went in cell by cell. Charts need a single block of cells, so 2 small chart-data blocks feed the line and bar charts. In footers, write '&&' for 1 ampersand. The HTML export has no charts.

VectorCraft. All files come from vectorcraft-cli run without a window. The mcp command was not used. graph.create drew every chart from the numbers in summary.json. Series colours go on the series group, and the graph keeps them. On a line chart, a fill on the series group also fills the line, so the script removes that fill. The chart tool has no data labels, so text.create added the end values at calculated positions. A probe run read the object ids for the label style; the ids stay the same for the same steps. The poster and deck charts use the same steps. They hide the title and use a smaller artboard.

DesignCraft. script and run worked without a window, and without --connect. Text colour must be a swatch name, so the script makes the palette swatches first. A raw hex colour gave invisible text. The bundled Inter font has only a Regular style, so the poster uses Segoe UI for bold text. A text frame that is too short hides its text, so each frame has room for its line height. The --page option counts from 0. vectorcraft-cli convert made a test image of the PDF for a visual check.

WordCraft. All work ran through wordcraft-cli with no window: run, convert, render, info and text. After insert.picture, the new picture stays selected, so the steps move the caret to the end first. After insert.footer, the caret stays in the footer, so the footer comes last. Formatting at the caret goes into the next paragraphs. The bold and grey text came last, with select.text. A page break inside a heading made a blank page, so the report uses widow control instead. Colours use the form {"Rgb":[r,g,b]}.

PdfCraft. All work ran through pdfcraft-cli with no window: combine, edit, extract, text, render, info and run --script. Text that PdfCraft adds with the standard fonts must use Western European characters. It refused the arrow character, so the cover uses words. Text from table pages comes out column by column, so the text sample uses page 2. The edit --rotate option works, but no page needed it: all pages read upright. PdfCraft does not write GIF files, so Python joined the frames.

DeckCraft. run, render and convert worked without a window. run has no references to earlier results, but a new object stays selected, so the next format command changes it. run writes only the last --save, so convert made the .pptx file. design.colors set the study colours, so the native chart uses them. The transitions and animations stay in the .pptx file. DeckCraft cannot render them to video or GIF, so a Python script made the GIF from the slide images. The PDF is about 2 MB because it contains the slide pictures at full size.

PhotoCraft. All steps ran through photocraft-cli run, convert and batch. No window opened. The .pcraft and .psd files keep all layers. PNG and JPG files have 1 flat layer. Text size is in points. Set the resolution to 72 ppi before you add text to high-ppi photos. The CLI has no animation export, so PIL joined the frames into the GIF.

LightCraft. render, merge, synth-merge, run --demo app.export and snapshot all ran without a window. The docs say that snapshot draws the full interface on the CPU, with no window and no GPU. A snapshot took about 1 second. app.export with a folder path wrote to the working folder, so the steps use a file path. The synthetic panorama preview had a visible seam, so the page does not use it. All source images are synthetic. The project uses no real photographs.

SoundCraft. All work used soundcraft-cli script, run and info. No window opened and no sound played. MIDI uses 960 ticks per quarter note. Synth settings cannot change from the command line, so insert effects shape the default synth sound. Bounce paths must be Windows paths (A:/...). Exports are WAV, AIFF or FLAC; there is no MP3. Python checked the level of each 2-second part; nobody played the audio.

EffectCraft. All work used effectcraft-cli script, render and render-frame. No window opened. The script engine has no String.substr; use substring. Text needs layer.property("Text").property("Source Text"). script --save-as saves the project even when the script fails, so check the output. The card uses the bundled Inter font. A 7-second render at 720p takes about 4 s on the CPU.

FilmCraft. All work used filmcraft-cli run, exec, render and probe. No window opened and no sound played. The PhotoCraft header and the GridCraft table are their v2 files; the edit waited for both .v2-ready markers. Clip and item numbers are in creation order, so the command list uses fixed numbers. A test import of the exported MP4 showed the burned-in subtitles. probe showed H.264 High, 1280x720, 30 fps, with AAC sound. Python measured the exported sound: peak -1.0 dBFS, RMS -18.3 dBFS. GIF frame times round to 120 ms, so the GIF plays about 4% fast. Subtitles sit at the bottom center, above the label: captions.setStyle {anchor: bottom, margin: 0.15}. The WebVTT file stores no position, so video players use their default bottom position.

CADCraft. cadcraft-cli run --cmd built the drawing from structured commands, with no window. convert made the PNG (dark background), the PDF and the SVG (white paper). The --window option made the close-up. Near-white lines disappear on white paper. For this reason, the text uses colour 7, which prints black. The SVG file is large because text becomes outlines and each hatch becomes many short lines. The SVG uses coarser hatches and comes as a ZIP file.
